# 视频生成工作台产品与技术方案

## 1. 项目概述

### 1.1 项目名称

视频生成工作台（Video Generation Workspace）

### 1.2 建设目标

为内容团队提供一个统一的视频生成作业台，解决以下问题：

1. 多条视频任务需要重复提交，效率低。
2. 任务分散在不同页面，无法集中查看进度和失败原因。
3. 视频生成完成后只能逐条下载，交付效率低。
4. API 地址、工作流和密钥修改不方便，联调成本高。

### 1.3 目标用户

- 内容运营：批量生成不同文案或镜头版本。
- 设计师：批量测试画面风格、分辨率和参考图。
- 项目负责人：查看批次进度、失败率和生成用量。

## 2. 产品范围

### 2.1 MVP 必须包含

| 模块 | 功能 |
| --- | --- |
| 批次创建 | 批次名称、统一参数、提示词列表、参考图 |
| 批量提交 | 一次提交多条任务，展示提交成功和失败数量 |
| 任务队列 | 全部、排队中、生成中、已完成、失败筛选 |
| 任务详情 | 提示词、参数、任务 ID、接口返回、错误信息 |
| 批量下载 | 勾选多个已完成任务，打包下载 ZIP |
| API 配置 | Endpoint、Workflow ID、API Key、演示模式开关 |
| 用量统计 | 本月生成数量、预计费用、成功率 |

### 2.2 第二阶段功能

- 任务重试和失败任务批量重试。
- 批次模板、常用提示词模板。
- 视频预览、封面截帧和单条下载。
- 上传本地参考图并自动转存对象存储。
- 团队成员、角色权限和操作审计。
- 导出任务 CSV，支持外部项目管理系统对接。

### 2.3 暂不纳入范围

- 在线视频剪辑、字幕编辑、配音混音。
- 多模型统一调度和自动择优。
- 面向终端客户的公开分享页面。

## 3. 核心用户流程

```text
进入工作台
  ↓
检查 API 连接与当前用量
  ↓
创建批次，填写批次名称和公共参数
  ↓
添加多条提示词，可逐条修改
  ↓
提交批次
  ↓
服务端创建任务并返回 task_id
  ↓
工作台轮询任务状态
  ↓
完成后勾选任务
  ↓
批量打包下载视频
```

部分任务失败时，批次不能整体失败：已成功的任务继续生成，失败任务单独显示原因并提供重试入口。

## 4. 页面与界面方案

### 4.1 页面结构

```text
┌──────────────┬───────────────────────────────────────────────┐
│ 工作区导航    │ 顶部栏：页面标题 / 服务状态 / 用户菜单         │
│              ├───────────────────────────────────────────────┤
│ · 工作台      │ 本月用量概览                                  │
│ · 任务记录    ├───────────────────────────────┬───────────────┤
│ · 素材库      │ 创建生成批次                    │ API 连接       │
│ · 用量账单    │ - 批次名称                      │ - 当前模型     │
│              │ - 时长 / 分辨率                  │ - 工作流 ID    │
│              │ - 提示词列表                     │ - 连接状态     │
│              │ - 参考图                         │ - API 设置     │
│              ├─────────────────────────────────┴───────────────┤
│              │ 任务队列：筛选 / 全选 / 批量下载 / 状态表格       │
└──────────────┴───────────────────────────────────────────────┘
```

### 4.2 创建批次区域

- 批次名称：便于后续检索和交付，例如“夏日品牌片-第一版”。
- 视频时长：默认 5 秒，限制 1–15 秒。
- 输出分辨率：480p、768p、横屏、1:1 等，选项由模型能力返回。
- 提示词列表：每行一个任务，支持新增、编辑、删除和拖拽排序。
- 参考图：支持 URL 或上传；显示格式和大小校验结果。
- 提交前显示预估费用和任务数量。

### 4.3 任务队列区域

表格字段建议如下：

| 字段 | 说明 |
| --- | --- |
| 选择框 | 用于批量下载和批量重试 |
| 任务 | 任务名称、task_id、提示词摘要 |
| 参数 | 分辨率、时长 |
| 状态 | 排队中、生成中、已完成、失败 |
| 进度 | 进度条或最近轮询时间 |
| 创建时间 | 用于排序和追踪 |
| 操作 | 预览、下载、重试、查看详情 |

### 4.4 API 设置抽屉

从右上角“管理 API 设置”进入，不离开当前工作台。配置项：

- API Endpoint。
- Workflow ID。
- API Key，默认密码掩码，可临时显示。
- 演示模式开关。
- 测试连接按钮。
- 保存设置按钮。

保存后只影响新提交的任务。当前任务保留提交时使用的配置版本，避免配置修改造成追踪混乱。

## 5. API 对接方案

### 5.1 前端与服务端边界

生产环境推荐：浏览器只访问工作台服务端，由服务端代理第三方视频 API。

```text
浏览器 → 工作台 API → 第三方视频 API
                  ← 任务结果 / 视频地址
```

这样可以避免把长期 API Key 暴露在浏览器、localStorage 或网络请求中。演示模式可以在浏览器本地运行，用于页面评审。

### 5.2 创建任务

```http
POST /api/workspace/batches
Content-Type: application/json
Authorization: Bearer <workspace-session-token>
```

```json
{
  "name": "夏日品牌片-第一版",
  "tasks": [
    {
      "prompt": "夏日午后，透明玻璃杯中的气泡水在阳光下闪闪发光",
      "duration": 5,
      "resolution": "768p",
      "reference_image": "https://example.com/reference.png"
    }
  ]
}
```

服务端再调用配置的第三方工作流接口，例如：

```http
POST {configured_endpoint}
Authorization: Bearer {configured_api_key}
Content-Type: application/json
```

### 5.3 查询任务

```http
GET /api/workspace/tasks/{task_id}
```

服务端负责适配第三方返回结构，统一返回：

```json
{
  "task_id": "task_xxx",
  "status": "completed",
  "progress": 100,
  "video_url": "https://signed.example.com/video.mp4",
  "error_code": null,
  "error_message": null
}
```

### 5.4 批量下载

```http
POST /api/workspace/downloads
Content-Type: application/json
```

请求任务 ID 列表，服务端流式生成 ZIP，返回一次性下载地址。避免浏览器同时触发大量下载，也便于做权限校验和审计。

## 6. 数据模型

### Batch

`id`、`name`、`task_count`、`completed_count`、`failed_count`、`estimated_cost`、`created_by`、`created_at`

### Task

`id`、`batch_id`、`prompt`、`duration`、`resolution`、`reference_image_url`、`provider_task_id`、`status`、`progress`、`video_url`、`error_message`、`created_at`、`completed_at`

### ApiConfig

`id`、`provider`、`endpoint`、`workflow_id`、`encrypted_api_key`、`is_active`、`updated_by`、`updated_at`

API Key 必须服务端加密存储；前端只能读取脱敏信息，例如 `D1xi••••q0myT`。

## 7. 状态机与异常处理

```text
created → queued → processing → completed
                         └────→ failed → retrying → queued
```

- 创建批次前校验提示词不能为空、数量不能超过单批上限。
- 第三方接口超时：自动重试 2 次，之后标记失败。
- 轮询采用 2 / 4 / 8 秒递增间隔，单任务最长 10 分钟。
- 批量提交采用部分成功策略，失败任务不影响其他任务。
- 视频地址使用带过期时间的签名 URL。
- 下载前再次校验用户对任务和批次的访问权限。

## 8. 安全要求

1. 测试 API Key 只用于测试环境，不能提交到 Git 或打包进生产前端。
2. 生产环境 API Key 使用服务端密钥管理或环境变量保存，并加密落库。
3. 参考图上传限制 MIME、文件大小和数量；服务端校验外部 URL，防止 SSRF。
4. 所有任务接口必须校验工作区权限。
5. 记录 API 配置变更、批次提交、批量下载等审计日志。

## 9. 实施计划

### Phase 1：原型评审（1–2 天）

- 确认页面布局、字段、状态和批量操作。
- 使用演示模式验证完整交互。

### Phase 2：MVP 开发（5–7 天）

- 工作台前端和任务队列表格。
- 服务端 API 代理、任务入库和轮询。
- API 设置和加密配置。
- ZIP 批量下载。

### Phase 3：稳定性（3–5 天）

- 失败重试、超时处理、幂等提交。
- 权限、审计、用量统计和监控告警。

## 10. 验收标准

- 一次批次可提交多条任务，并能看到每条任务的独立状态。
- 提交接口失败时，不会重复创建任务；重新提交具有幂等键。
- 任务完成后显示视频地址，并可选择多个任务打包下载。
- API Endpoint、Workflow ID、API Key 可在工作台修改。
- API Key 在界面默认隐藏，生产环境不落浏览器 localStorage。
- 网络异常、接口超时和单条失败均有明确提示及重试路径。
- 480p / 768p、横屏 / 方形等参数与实际模型能力保持一致。
